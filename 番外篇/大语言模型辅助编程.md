## 大语言模型辅助编程

近几年，以 ChatGPT 为代表的大语言模型（Large Language Model，简称 LLM）发展得非常迅速，越来越多的同学开始把这些模型当作学习编程和编写代码的助手。这一篇番外篇，我们就来聊一聊：大语言模型是怎么回事，怎么跟它"对话"才能得到好的回答，以及在编程学习和开发中，它到底能帮我们做哪些事情，又有哪些局限和需要注意的地方。

### 大语言模型概述

#### 基本原理

**大语言模型**本质上是一种基于深度神经网络的文本生成模型，它的核心思想可以概括为两句话：

- **海量文本预训练**：模型在训练阶段会"阅读"互联网上数以万亿计的网页、书籍、代码、论文等文本，从中学习语言的规律，包括词汇的搭配、语法结构、事实知识，甚至代码的写法。
- **按概率逐词生成**：模型并不"知道"答案，它做的是根据上文内容，计算下一个词（或字、Token）出现的概率，然后按概率选出一个词接上去，再接着预测下一个词，如此反复，直到生成完整的回答。

> **说明**：Token（词元）是大语言模型处理文本的基本单位，一个英文单词可能是一个 Token，一段中文可能按一至几个字切分成 Token，代码中的变量名、符号同样会被切分成 Token。模型的很多能力限制（如单次对话的最大长度）都是以 Token 数来衡量的。

正因为是"按概率生成"，模型的回答具有不确定性：同样的问题问两次，可能得到措辞甚至内容都不同的回答。这一点在后面讲局限时还会提到。

#### 什么是提示词（Prompt）

我们发给大语言模型的文字，叫做**提示词**（Prompt），也有很多人直接叫它"提示"或"提示语"。提示词的质量直接决定了模型回答的质量——同一个模型，会问的人和不会问的人，得到的答案可能天差地别。

一个结构良好的提示词，通常包含下面几个要素：

| 要素 | 作用 | 示例 |
| ---- | ---- | ---- |
| **角色** | 给模型设定身份，让它按该领域的口吻和知识水平回答 | "你是一位有十年经验的 Python 讲师" |
| **任务** | 明确告诉模型要做什么，越具体越好 | "解释什么是字典推导式，并给出 3 个例子" |
| **约束** | 限定回答的形式、长度、范围、语言等 | "用中文回答，代码不超过 20 行，面向零基础读者" |
| **示例** | 给出输入输出的样例，让模型模仿 | "例如：输入 [1, 2, 3]，输出 {1: 'odd', 2: 'even', 3: 'odd'}" |

> **提示**：写提示词可以记住一个简单的公式——**"你是谁 + 做什么 + 有什么要求 + 最好给个例子"**。四样齐全，模型的回答通常会更贴合需求。

举个例子，下面这个提示词就同时包含了角色、任务、约束和示例：

```text
你是一位面向零基础学习者的 Python 老师（角色）。
请解释 Python 中 enumerate 函数的作用（任务），
要求：用中文回答，给出一段带注释的示例代码，代码不超过 10 行（约束）。
示例输出格式：先一句话解释，再给代码（示例）。
```

> **说明**：如果对第一次的回答不满意，可以在对话中继续追问和纠正，例如"把代码改成用列表推导式实现""再举个实际应用的例子"，这种多轮对话往往会得到比单次提问更好的结果。

#### 常见的大语言模型

目前国内外的产品很多，下面列举一些常见的，方便大家选择。

- **国内**：百度的**文心一言**、阿里的**通义千问**、智谱AI的**智谱清言**（GLM 系列）、深度求索的 **DeepSeek**、月之暗面的 **Kimi** 等。
- **国外**：OpenAI 的 **ChatGPT**、Anthropic 的 **Claude**、Google 的 **Gemini** 等。

接入这些模型的方式主要有三种：

1. **网页对话**：打开官网注册后直接在浏览器里对话，零门槛，适合日常问答和学习。
2. **API（应用程序接口）**：向官方申请密钥，编写程序调用模型接口，适合想把大模型能力集成到自己应用里的开发者（通常按 Token 用量付费）。
3. **IDE 插件 / 编程助手**：在编辑器中安装的辅助编程工具，例如 **GitHub Copilot**，以及国内厂商推出的代码助手插件。这类工具能在编写代码时自动补全、解释代码、生成函数实现，与开发流程结合得最紧密。

### 大模型辅助编程的典型场景

下面我们通过四个最常见的场景，看看如何借助大模型来辅助编程。每个场景都会给出提示词示例，并说明使用时的注意事项。

#### 代码参考：生成代码骨架

当我们不太清楚某个功能怎么下手时，可以让模型先生成一个代码骨架，再在此基础上修改完善。

提示词示例：

```text
你是一位 Python 开发工程师。请帮我写一个函数的代码骨架：
功能是统计一个文本文件中每个单词出现的次数。
要求：只需给出函数结构和关键步骤的注释，不需要完整实现细节，
使用 Python 3，附简要说明。
```

模型的回答可能是这样的：

```python
def count_words(filepath):
    """统计文本文件中每个单词出现的次数。"""
    # 1. 打开文件并读取全部内容
    with open(filepath, 'r', encoding='utf-8') as f:
        text = f.read()
    # 2. 将文本转换为小写并拆分成单词列表
    words = text.lower().split()
    # 3. 用字典统计每个单词出现的次数
    counter = {}
    for word in words:
        counter[word] = counter.get(word, 0) + 1
    # 4. 返回统计结果
    return counter


if __name__ == '__main__':
    result = count_words('hello.txt')
    print(result)  # 结果：{'hello': 2, 'world': 1}（取决于文件内容）
```

注意事项：

- 模型给出的骨架是**参考**，不是最终答案，一定要自己读一遍、动手改一遍。
- 明确说出运行环境（如 Python 3.8、是否允许使用三方库），否则模型可能用到你环境中没有的东西。

#### 代码调试：贴报错信息问

程序报错看不懂时，可以把**报错信息和相关代码**一起贴给模型，请它帮忙定位原因。

提示词示例：

```text
你是一位 Python 调试助手。我的代码运行报错了，请帮我分析原因并给出修改方案。
报错信息如下：
TypeError: can only concatenate str (not "int") to str
我的代码如下：
age = input('请输入年龄：')
print('你今年' + age + '岁了，明年' + age + 1 + '岁')
```

> **提示**：这类问题模型的回答通常很准确——上面的错误是因为 `age` 是字符串（`input` 函数的返回值），`age + 1` 试图把整数加到字符串上，需要先用 `int(age)` 做类型转换。贴报错时请保留完整的 `Traceback`，最后一行之外的信息（哪个文件、哪一行）同样重要。

注意事项：

- 贴代码时只贴**必要的部分**，避免把不相关的代码全部粘贴进去干扰分析。
- 如果代码涉及公司或学校的内部业务逻辑，请注意脱敏（见下文学术诚信与数据安全部分）。
- 模型给出的修复方案要**实际运行验证**，不要只看文字描述就认为对了。

#### 代码优化：请求重构建议

对于能跑通但写得不优雅的代码，可以让模型提出优化和重构建议。

提示词示例：

```text
你是一位熟悉 Python 惯用写法（Pythonic）的工程师。
请对下面这段代码提出优化建议，指出可以改进的地方，
并用更简洁的方式重写，逐条说明理由：
for i in range(len(fruits)):
    print(str(i + 1) + '. ' + fruits[i])
```

> **说明**：像上面这种用 `range(len(...))` 加下标遍历列表的写法，模型一般会建议改用 `enumerate(fruits, start=1)`，既简洁又不易出错。此外，它还可能建议用 f-string 替代字符串拼接。这些优化建议通常很有价值，但采纳前要确认改写后的代码行为与原来一致。

注意事项：

- 优化前可以要求模型"保持功能不变"，并自己准备几组输入对比优化前后的输出。
- 性能优化方面，模型的建议有时是凭直觉的，关键代码可以用 `timeit` 等工具实测对比。

#### 编程学习：解释概念、逐行讲解

把模型当作随问随答的老师，是这个场景里最实用的用法——它可以解释概念、逐行讲解代码、出练习题。

提示词示例：

```text
你是一位面向零基础学习者的 Python 老师。
请逐行讲解下面这段代码，每一行都用一句中文说明它做了什么，
最后用一段话概括整段代码的功能：
squares = {x: x ** 2 for x in range(1, 6)}
print(squares)
```

模型的回答可能是这样的：

```text
第 1 行：使用字典推导式，遍历 1 到 5 的每个整数 x，
        以 x 为键、x 的平方为值，构造一个字典 squares。
第 2 行：调用 print 函数，把字典 squares 的内容输出到屏幕。
概括：这段代码生成了一个 1 到 5 的数字及其平方的对照表，
     运行结果为 {1: 1, 2: 4, 3: 9, 4: 16, 5: 25}。
```

注意事项：

- 解释概念时可以追问"能不能再举个生活中的例子""初学者最容易在什么地方犯错"，帮助加深理解。
- 对于难度较高的知识点，可以让模型"分步骤、由浅入深"地讲解，而不是一次性堆出全部细节。
- 学编程不能只看不练——让模型出几道练习题并自己独立完成，比单纯读讲解效果好得多。

### 使用大模型的思考

#### 能力与局限

大语言模型的能力是有目共睹的：回答速度快、知识面广、能写会改、态度耐心。但它也有几个**必须警惕的局限**：

- **幻觉（Hallucination）**：模型可能一本正经地编造不存在的东西，比如虚构的函数、不存在的库、错误的参数名，甚至伪造"参考资料"。越是生僻的主题，幻觉越容易出现。
- **生成过时的 API**：模型的训练数据有时间截止点，一些库更新得很快（例如某个函数在新版本中被废弃或改名），模型给出的写法可能已经过时，实际运行时要以官方文档为准。
- **知识边界模糊**：模型无法感知自己"不知道"，回答的语气始终是自信的，**不能因为回答读起来流畅就认为它正确**。

> **提示**：最可靠的判断方式是**用代码说话**——把模型给的代码实际运行一遍。跑得通、结果对，才是真的好。

#### 辅助而非替代

大模型可以加速编码、辅助学习，但它不能替代学习者本身：

- 初学阶段如果全靠模型生成代码，跳过了自己思考、动手、踩坑的过程，学到的只能是"看起来会了"。
- 遇到问题时，正确的顺序应该是**先自己尝试**（读报错、查文档、写小实验），实在解决不了再求助模型，并把它的解答当作一次学习机会，看懂为止。
- 在真实开发中，需求理解、架构设计、对业务负责的能力，目前仍然是人不可替代的部分。

#### 学术诚信与数据安全

最后两点，请大家务必记牢：

- **学术诚信**：在课程作业、考试、论文中，如果使用大模型辅助，必须遵守学校或机构的规定，按要求进行说明和标注。直接把模型生成的代码或论文当作自己的作业提交，属于学术不端行为。
- **数据安全**：通过网页或 API 使用大模型时，输入的内容可能会被服务商记录和处理，因此**不要提交机密代码**，包括公司的核心业务代码、密钥和账号密码、他人隐私数据等。敏感信息务必脱敏后再提问。

### 总结

大语言模型通过海量文本预训练，学会了按概率逐词生成文本，我们可以通过角色、任务、约束、示例四要素写出高质量提示词，让它在代码参考、代码调试、代码优化、编程学习等场景中成为得力助手。但也要清醒地认识到它可能产生幻觉、给出过时 API 等局限，用运行代码来验证答案，把它当作辅助而非替代，同时守住学术诚信和数据安全的底线，才能真正让大模型为我们的编程学习锦上添花。
