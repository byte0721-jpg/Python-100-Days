## 用PyInstaller打包程序

我们写好的 Python 程序是 `.py` 源代码文件，想让别人也能运行它，对方电脑上就得安装 Python 解释器和程序用到的各种三方库，这显然很麻烦。**PyInstaller** 是一个非常流行的第三方工具，它可以把我们的 `.py` 脚本（包括用到的解释器、三方库和资源文件）打包成一个**可执行文件**（Windows 下就是 `.exe` 文件），别人拿到这个文件后**不需要安装 Python 环境**就能直接双击运行，非常适合分发小程序和小工具。

### 安装PyInstaller

PyInstaller 是第三方库，需要先用 `pip` 安装，在命令行（终端）中执行下面的命令即可。

```text
pip install pyinstaller
```

> **说明**：PyInstaller 是把源代码"打包"成可执行文件的工具，安装好之后它主要作为**命令行工具**使用，而不是在代码里 `import` 使用的库。

安装完成后，可以在命令行输入下面的命令查看版本号，能正常显示就说明安装成功了。

```text
pyinstaller --version
```

### 打包步骤

打包的整体流程可以概括为三步：

1. **准备脚本**：把要打包的 Python 脚本准备好，最好先手动运行一次，确认脚本本身没有任何问题。
2. **执行命令**：打开命令行，切换到脚本所在的目录，执行 `pyinstaller` 命令。
3. **获取结果**：命令执行完成后，在脚本所在目录下生成的 **`dist` 目录**中找到打包好的可执行文件。

#### 一个完整的例子

假设我们有一个简单的脚本 `hello.py`，内容如下：

```python
name = input('请输入你的名字: ')  # 提示用户输入名字
print(f'{name}, 你好, 欢迎使用 Python!')  # 向用户问好
```

在命令行中切换到 `hello.py` 所在的目录，执行：

```text
pyinstaller -F hello.py
```

命令执行过程中会输出一大段日志信息，执行结束后，目录结构大致如下：

```text
hello.py
build/          <-- 打包过程的临时文件，可以删除
dist/           <-- 打包结果所在目录
    hello.exe   <-- 打包好的可执行文件（Windows 下）
hello.spec      <-- 打包配置文件，记录打包时的选项
```

双击 `dist` 目录下的 `hello.exe`，程序就能脱离 Python 环境直接运行了。

> **提示**：`build` 目录存放的是打包过程中的中间产物，发布程序时只需要 `dist` 目录中的结果，`build` 目录可以放心删除。`.spec` 文件是打包的配置文件，如果以后要重新打包，可以直接基于它操作。

### 常用参数

`pyinstaller` 命令支持很多参数（选项），常用的有下面这些：

| 参数 | 作用 |
| --- | --- |
| `-F` | 把程序打包成**单个**可执行文件（默认会打包成包含很多文件的一个文件夹） |
| `-D` | 打包成一个文件夹（目录），这是默认方式，启动速度通常比单文件模式快 |
| `-i 图标文件` | 给可执行文件**指定图标**，例如 `-i app.ico` |
| `-w` | 打包**图形界面程序**时使用，运行时**不弹出控制台窗口**（黑窗口） |
| `-c` | 运行时显示控制台窗口，这是命令行程序的默认行为 |
| `--clean` | 打包前清理上一次打包留下的缓存和临时文件，避免旧文件干扰 |
| `-n 名称` | 指定生成的可执行文件的名称，不指定时默认使用脚本名 |
| `--add-data 源文件;目标路径` | 把脚本需要的非代码资源（图片、配置文件等）一起打包 |

> **说明**：`--add-data` 参数中源文件和目标路径的分隔符在 Windows 上是分号 `;`，在 macOS 和 Linux 上是冒号 `:`。

#### 参数组合示例

下面这条命令把 `game.py` 打包成单个可执行文件，指定图标为 `game.ico`，并且运行时不显示控制台窗口，同时清理上次打包的缓存：

```text
pyinstaller -F -i game.ico -w --clean game.py
```

> **提示**：`-w` 参数只适合打包使用 tkinter、PySide 等图形界面库的程序。如果给普通的命令行程序加上 `-w`，程序运行时连输入输出的窗口都没有，会让人误以为程序"没反应"。

### 常见问题

#### 杀毒软件误报

自己用 PyInstaller 打包出来的 `.exe` 文件，有时会被杀毒软件当作病毒拦截或删除。这是因为打包生成的可执行文件"外壳"特征明显，容易被误判。遇到这种情况可以尝试以下做法：

- 把文件加入杀毒软件的**白名单**（信任列表）；
- 打包时加上 `--clean` 参数重新打包；
- 换用 PyInstaller 的最新版本，新版通常会改进这方面的表现。

#### 路径问题

程序打包后，运行时的工作目录可能和开发时不一样。如果在代码里用**相对路径**去读取图片、配置文件等资源，打包成单文件模式后很可能出现"找不到文件"的错误。正确的做法是基于程序自身的位置来构造路径：

```python
import os
import sys

# 获取程序（可执行文件或脚本）所在目录的完整路径
base_path = os.path.dirname(os.path.abspath(sys.argv[0]))
# 拼接出资源文件的完整路径，这样无论从哪里启动程序都能找到资源
config_path = os.path.join(base_path, 'config.ini')
print(config_path)  # 结果：C:\tools\demo\config.ini（视程序实际位置而定）
```

> **提示**：PyInstaller 会把运行时路径相关的信息放在 `sys._MEIPASS` 属性中（单文件模式下资源被解压到一个临时目录），需要读取"打包进去的资源"时可以使用它，网上有很多相关资料可以进一步了解。

#### 打包后文件变大

很多人第一次打包会被结果吓一跳：几十行的脚本，打包出来却有好几兆甚至几十兆。原因主要有两个：

1. PyInstaller 会把 Python **解释器本身**和程序**用到的所有依赖库**都打进可执行文件里，所以体积自然小不了；
2. 如果不小心把用不到的库也打包了进去（例如用 `conda` 环境打包时，环境里装的库太多），文件会进一步膨胀。

减小体积的常用做法：

- 使用**干净独立的虚拟环境**打包，环境里只安装程序真正需要的库；
- 确认没有导入用不到的模块，必要时用 `--exclude-module 模块名` 参数排除不需要的库；
- 单文件模式（`-F`）启动时会先解压到临时目录，体积和启动速度方面可根据需要选择单文件或文件夹模式。

###  总结

PyInstaller 可以把 Python 脚本打包成脱离解释器运行的可执行文件，通过 `pip install pyinstaller` 安装后，使用 `pyinstaller -F 脚本名.py` 这类命令即可完成打包，打包结果在 `dist` 目录中；常用参数包括 `-F`（单文件）、`-i`（指定图标）、`-w`（不显示控制台）、`--clean`（清理缓存）等；遇到杀毒软件误报、路径找不到、体积过大等问题时，可以分别通过白名单、基于程序位置构造路径、干净虚拟环境打包等方式解决。
